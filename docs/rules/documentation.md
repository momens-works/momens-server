# 문서·주석

작성 전 독자가 해야 할 판단이나 행동과 기존 정본을 확인합니다. 기존 문서에 필요한 설명을
보완할 수 있으면 새 문서를 만들지 않습니다. 문서 분류는 [문서 인덱스](../README.md)를 따릅니다.

## 무엇을 어디에 남기는가

- 현재 유효한 계약·상시 규칙·운영 절차는 저장소 문서에 둡니다. 코드·OpenAPI·도구 schema에서
  확인 가능한 필드·enum·구현 목록을 다시 나열하지 않습니다. 비동기 상태나 재시도 조건처럼
  해당 정본만으로 알 수 없는 의미는 남깁니다.
- 작업 배경·대안 검토·완료 보고·일회성 측정 결과는 관련 티켓·PR에 보존합니다. 운영 판단에
  계속 필요한 측정 기준·결과·재검증 의무는 현행 운영 문서에 남깁니다.
- 장기적으로 중요한 결정과 근거는 [ADR](../adr/README.md)에 남깁니다.
- 완료된 스프린트 요구사항은 유효 계약만 기존 문서에 합칩니다. 과거 범위·요구사항 ID·완료
  이력은 티켓·PR 및 고정 커밋에 보존하고 미결 항목의 추적 위치를 확인한 뒤 문서를 정리합니다.
  별도 archive 문서를 기본값으로 늘리지 않습니다.
- 유효 계약·운영 절차·미완료 결정은 대체 확인 위치 없이 삭제하지 않습니다. TODO는 코드와
  티켓 상태를 대조하고, 미배정·미확정이면 그 상태를 명시합니다. 정리 완료를 기능 완료나
  정책 확정으로 간주하지 않습니다.

## 주석과 참조

- 코드와 이름을 그대로 반복하는 주석은 생략합니다. 구현 이유, 비자명한 계약·불변식,
  동시성·트랜잭션·보안·성능 제약, 우회 구현의 근거를 필요한 위치에 짧게 남깁니다.
- 주석이 주장하는 보장과 인과관계를 실제 코드와 대조합니다. 잘못된 설명을 고칠 때도 그
  파일의 책임 밖 설명을 늘리거나 다른 정본의 규칙을 복제하지 않습니다.
- 독자의 다음 행동에 필요한 참조만 남깁니다. 설명을 지운 자리마다 링크를 추가하거나
  서로를 가리키는 문서를 만들어 참조 단계를 늘리지 않습니다.
- 파일·제목·공개 타입을 삭제하거나 옮기면 들어오는 링크와 Javadoc 참조도 확인합니다.
  라이선스, 도구 지시문, suppression, 렌더링 조건부 주석은 일반 설명과 구분합니다.
  적용된 Flyway의 주석은 checksum에 영향을 주며, 스크립트 주석이 도움말로 출력되는 경우도
  있으므로 주석 변경이 항상 비동작 변경이라고 가정하지 않습니다.

## 검토와 검증

- PR에서는 위 기준을 변경된 문서와 코드 주석에 적용합니다. 주석 길이·개수 제한이나
  키워드 탐지로 의미 판단을 대체하지 않습니다.
- 로컬 링크와 Javadoc 참조는 아래 자동 검사 절차를 따릅니다. 자동 검사가 다루지 않는
  코드 주석의 문서 경로나 테스트 소스의 Javadoc은 변경 대상과 유입 참조를 직접 확인하고
  검증 범위를 PR에 기록합니다. 컴파일 성공만으로 Javadoc 링크의 유효성을 판단하지 않습니다.
- 설명만 바꾸는 작업도 포맷과 동작 영향을 확인합니다. 실행 코드·문자열·설정값이 함께
  바뀌면 비동작 변경으로 보고하지 않습니다.

## 자동 검사

문서 변경 시 링크 검사를, Java 주석이나 참조 대상 선언 변경 시 Javadoc 검사를 실행합니다.
명령은 저장소 루트 기준입니다.

```bash
bash scripts/check-doc-links.sh
./gradlew javadoc
```

- 링크 검사는 [lychee](https://lychee.cli.rs/)로 Git 추적 `*.md` 전체와 Git 제외 대상이 아닌
  새 `*.md`의 로컬 파일·이미지·제목 앵커·명시적 HTML 앵커를 확인합니다. `.codex`·`.claude`
  문서도 포함하며, 파일 삭제·제목 변경으로 깨지는 다른 문서의 유입 링크도 검사합니다.
- [설치 스크립트](../../scripts/install-lychee.sh)가 버전·플랫폼별 archive SHA-256을 고정합니다.
  최초 실행에는 curl·tar·SHA-256 도구와 다운로드 네트워크가 필요하며, `build/tools/`에
  설치합니다. 도구 갱신 시 버전·checksum을 함께 바꿉니다.
- 검사 자체는 오프라인입니다. 외부 URL의 접속 상태, 코드 블록·인라인 코드의 예시, 일반
  텍스트로 적은 경로와 Java 주석은 링크 검사 대상이 아닙니다. Markdown 파서가 링크로 인식하지
  않는 문법까지 검증한다고 보지 않습니다. 대상 파일은 작업 트리에서 확인하므로 로컬에서만
  존재하는 파일로 인한 누락은 깨끗한 CI checkout에서 최종 확인합니다.
- Javadoc은 모든 모듈의 `main` 소스에서 private 선언까지 `reference` doclint를 적용합니다.
  타입·멤버 참조 오류를 차단하며, 주석 누락·문장 품질·외부 URL 상태를 검사하지 않습니다.
  테스트 소스의 주석은 이 task에 포함되지 않습니다.
- CI의 필수 `pr-format`은 링크 검사와 `bash scripts/check-doc-links-test.sh`를,
  `build`의 Gradle `check`는 Javadoc을 실행합니다. 검사 도구 수정·갱신 시에는 로컬에서도
  회귀 테스트를 실행합니다.
